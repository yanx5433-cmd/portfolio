01一条目标进来，会发生什么

Agent 的难点不在“能调工具”，而在它决定调什么的时候，你还能不能拦住它。 这条链路里每一站都可能把任务停下，而且停下必须留下痕迹。

GATE 1
输入拦截
「删库」「rm -rf」这类高危目标不进规划器，直接 blocked 并落轨迹。
PLAN
双引擎规划
规则模板默认在线；有 Key 时让模型出 JSON 计划，再逐条校验，不过就回落。
GATE 2·3
授权与消毒
写操作逐名授权；参数按声明校验类型与取值域，未知参数剔除。
EXECUTE
拓扑执行
依赖排序、单步超时、只读失败重试一次；单步失败不炸全局。
GATE 4
引用闸门
结论逐句查 [ev:id]，查不到证据的句子删掉而不是标黄。
↻ 反思站：证据不足时自动补只读步骤，最多 2 轮，且永不自动引入写操作 ⏱ 预算站：步骤 10 / 工具 14 / LLM 6 / 单步 10s，超即熔断

02主打作品 · OpsPilot 巡检与故障诊断智能体

运维/技术支持场景里，“AI 帮我看看服务器怎么了”通常有两种结局：要么只能聊天给建议， 要么真给了 shell 权限。我选择第三条：能力全部声明为受审工具，判断过程全部落成可回放轨迹。

开源 · MITPython 3.11+ FastAPI 面板GitHub Actions 无 Key 全功能
yanx5433-cmd/opspilot-agent ↗

它解决的具体问题

值班时收到一条告警，人要花二十分钟在指标、日志、手册、历史故障之间来回跳， 还得写一份能交出去的记录。OpsPilot 把这二十分钟压成一次运行：给出根因排序、对应手册步骤、 配置整改项、容量外推，并把每一步为什么这么做写进 JSONL 轨迹。

关键取舍：结论里出现一个证据里没有的数字，宁可把这句话删掉、 把任务降级成 partial，也不让它留在答复里显得完整。
ADR-001
规则优先，LLM 是增强
规划与综合各两条实现。模型超时、返非法 JSON、给出未知工具，都回落规则模板并记 fallback_reason。无人值守不该因为一个 503 就断巡检。
docs/ADR.md
ADR-002
裁句子，不标黄
引用闸门按句检查证据 id 与数字溯源。误伤也真实发生过：序号「步骤 3」被判成无源数字、阻塞清单被删成空标题——掩盖失败比丢失措辞严重，两处都留了测试。
app/agent/synthesizer.py
ADR-003
不给 Agent shell
运行时零 subprocess。14 个工具都是显式函数，写操作默认挂起等人工授权；http_probe 带目标白名单堵 SSRF。元字符检查刻意放过单个 |——日志 pattern 是正则。
app/agent/guardrails.py
算法
判断力可复算
BM25（中文 bigram，零依赖）检索手册；EWMA 控制限检异常（不用全局 z-score，磁盘是慢变趋势）；最小二乘外推“几天写满”，R²<0.6 直接拒答。
app/algos.py
评测
含阴性对照
金标用例断言工具序列、证据覆盖、护栏命中、引用完整性。数据里放了一台全程健康的 cache-01：Agent 不许在它身上无中生有。
evals/cases/
诚实边界
写了局限清单
合成数据、阈值未标定、“概率”实为相对占比未校准、LLM 分支在 CI 里只被 mock 覆盖、面板无鉴权不可公网。见 docs/LIMITATIONS.md。

04我按什么标准做作品集

参考了大厂开源项目与几份内部技术评审的写法之后，我给自己定了四条硬要求——它们比代码量更能说明问题。

01 / REPRODUCIBLE
可复现优先于好看
演示数据由固定种子生成，异常是显式注入的。面试官在自己机器上跑，结果和我这儿逐行一致，不存在“我这儿是绿的”。
02 / MEASURABLE
能力要能被断言
“防幻觉”不是形容词：它等于引用裁撤条数、无证据句比例、数字溯源失败数三个可测指标，并且有一条用例专门检查阴性对照主机不被误报。
03 / DOCUMENTED
决策与代价一起写
六篇 ADR 都带“付出了什么代价”和“什么时候该推翻它”。只写正确决定的文档，等于没写。
04 / HONEST
局限单独成页
合成数据不代表生产分布；“概率”没做校准；LLM 分支在无 Key 的 CI 里只被 mock 覆盖；面板没有鉴权不能公网。写在 README 第一屏能看见的地方。
